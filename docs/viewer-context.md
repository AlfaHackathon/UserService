# Canonical account context and immutable viewer framing

One existing account UUID remains the identity for F/U input. Nullable `users.source_person_id` is F-source lineage only; it is not an account alias or a membership grant. An explicit new capture may correct or clear this lineage on the same existing account; it never rekeys the account or creates/changes membership. Nullable `city_name` and `rc_name` map only known `CITY_NAME` and `RC_NAME` service-geography columns. They describe where service is provided, not company registration or operation. Other CSV fields remain pending the actual header. Required auth fields, the account role and the single-company membership constraint are unchanged. This change contains no CSV importer, account creation, password generation, ACL assignment or seed/backfill.

`POST /user-service/internal/users/{userId}/viewer-context?companyId={companyId}` requires the existing `X-Internal-Secret` and an existing account with current membership in that company. Body: `{ "revisionId": "capture-1", "sourcePersonId": null, "serviceGeography": { "cityName": null, "rcName": null }, "provenance": { "sourceId": "actual-source-id", "versionId": "actual-version", "contentHash": "<exact lowercase SHA256 of the supplied original>" } }`. The trusted producer must provide an actual immutable source reference; the endpoint does not infer a CSV source, location, company or access right from lineage. All body fields are explicit; unknown extra fields and invalid identifiers are rejected. Null means unknown or explicitly cleared canonical context. Capture reads the exact existing default/custom role; null assignment stays null. It derives `knownAt` from the server clock and atomically writes a snapshot and the nullable canonical columns. No timestamp or role is accepted from the caller. Identical revision/body replays return the original snapshot without recapturing the current role or changing canonical fields; changed body under the same revision returns 409. Captures serialize per existing account and reject non-increasing knowledge time.

`GET /user-service/internal/users/{userId}/viewer-context?companyId={companyId}&asOf={timestamp}` requires the same internal secret and checks current membership before reading. It returns only the newest stored snapshot with `knownAt <= asOf`; missing state returns 404, with no current-role/geography fallback and no snapshot creation. Past snapshots retain their captured role even after assignment changes. Callers derive identity from the trusted gateway or persisted chat owner, never model arguments.

The safe response allowlist is `{ userId, companyId, revisionId, knownAt, contentHash, sourceOwner: "user-service", role: { id, name, isDefault } | null, serviceGeography: { cityName, rcName }, provenance: { sourceId, versionId, contentHash } }`. It excludes names, email, password hashes, source-person lineage and read grants. The outer content hash is SHA256 of UTF-8 web JSON in this property order: `userId, companyId, revisionId, knownAt, sourceOwner, role, serviceGeography, provenance`; `contentHash` itself is excluded. The provenance hash remains the source original's exact hash. The response describes declared viewer context, never documentary financial exposure. Role and service geography can frame questions and actions; canonical facts, calculations, company location and ACLs must not be rewritten from them.

Service-geography values retain source text exactly: `null`, `""`, spaces, tabs, Unicode and leading/trailing spacing remain distinct in canonical TEXT columns, snapshots and hashes. No trim, blank-to-null conversion or Unicode normalization is applied. A source encoding/normalization contract has not been supplied. Each nullable geography string has a 16000 UTF-16-code-unit request resource bound; PostgreSQL-incompatible NUL is rejected. Capture bodies are limited to 64 KiB (413 when exceeded). These are storage/request limits, not inferred source field widths; role names retain their existing separate validation rules.

Status codes: malformed/absent required scope or fields 400; missing internal secret 401; missing or different current membership 403; missing account/snapshot 404; immutable capture conflict 409; unavailable membership or unverifiable assigned/saved context 502. No failure implies a successful null role. The additive `20261026001` migration adds only nullable context columns and immutable snapshot storage; historical rows are not synthesized.

DB-free checks: `dotnet run --project tests/ResourceSmokeTest/ResourceSmokeTest.csproj` exercises actual service/controller behavior with repositories and membership fakes plus existing SQL-resource checks. `dotnet run --project tests/ViewerSnapshotContractTest/ViewerSnapshotContractTest.csproj` compiles the actual DTO/hash policy without private packages and checks nulls, exact hash, source isolation, historical time, safe output and rejected backdating. Neither runner starts a database, model, container or external stack. Full native build/first runner still require the repository's private NuGet packages.
