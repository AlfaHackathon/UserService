# Canonical source part of a User account

The complete source header is exactly `SYNTHETIC_F;CITY_NAME;RC_NAME;SYNTHETIC_U`. The owner contract uses the already-converted UUID account identity `UserId = UUID(F,U)`, `SourcePersonId = UUID(F)` and `CompanyId = UUID(U)`. UUID conversion and bulk CSV import are outside this change. No dataset is loaded. `CITY_NAME` and `RC_NAME` remain raw nullable service geography; null, empty, whitespace and Unicode retain their exact distinction, with the existing 16000 UTF-16-unit/no-NUL storage bound and 64 KiB capture body limit. No company registration/operating region is inferred.

`UserSourceAccountProfile` is the canonical source part of the same logical User account, not another Client domain or a multi-company login. `user_source_accounts` has PK `user_id` and UNIQUE `(source_person_id, company_id)`; its identity pair is immutable. `user_source_account_revisions` holds immutable geography/provenance snapshots. Its only FK is to the canonical source identity. There is no FK to an auth User row or another service's Company table, and no auth credentials/names/passwords, membership, roles or grants are generated. A source-only account can therefore exist before an optional login account. The source profile omits role because the source contains no role; authenticated role framing continues through the existing membership-checked viewer snapshot contract.

All routes require the existing internal secret. `POST /user-service/internal/source-accounts/{userId}/context` accepts `{sourcePersonId,companyId,revisionId,serviceGeography:{cityName,rcName},provenance:{sourceId,versionId,contentHash}}`, all UUIDs/exact source metadata supplied by a trusted caller. Capture assigns actual server `knownAt` and an immutable hash; it accepts no caller timestamp or role. Same revision/body replays exactly; changed body/rebound pair/duplicate pair/knowledge-time conflicts return 409. A new revision may change only geography/provenance, never either identity key. Invalid payloads return 400. For an already auth-backed UUID, the write verifies current membership in the source company; absent/different membership returns 403 and unavailable verification 502. Non-null auth source lineage must also match inside the transaction. A canonical-only UUID never calls CompanyService.

`GET /user-service/internal/source-accounts/{userId}/context?asOf=...` and `GET /user-service/internal/source-accounts/by-pair?sourcePersonId=...&companyId=...&asOf=...` return the same latest source profile with `knownAt <= asOf`, or 404. Both require explicit historical scope. Pair resolution does not expose a future-known identity merely because a current mapping exists. Reads never create snapshots and never fall back to current geography or login roles. The owner-only DTO is `{userId,sourcePersonId,companyId,revisionId,knownAt,contentHash,sourceOwner:"user-service",serviceGeography,provenance}`; lineage remains absent from the separate safe viewer DTO. The content hash is SHA256 of UTF-8 web JSON in this property order, excluding `contentHash`: `userId,sourcePersonId,companyId,revisionId,knownAt,sourceOwner,serviceGeography,provenance`.

The existing viewer capture validates membership/scope first, then returns an exact stored revision replay before checking a newly present canonical identity. Thus an immutable historical capture with null lineage can be retried without writing/rebinding after a canonical pair appears; a new capture with null/different lineage or a different company is rejected in preflight and again transactionally. Both write transactions first take the same `SHARE ROW EXCLUSIVE` lock on `user_source_accounts`, then an auth row lock if one exists. This small serialization seam prevents identity-creation/viewer-write races and pair duplication without another database or lock service. Existing auth-role assignments and the single-company-membership constraint are unchanged. New source capture never updates auth User rows, roles or membership. The additive `20261027001` migration creates empty canonical tables, with no backfill/provisioning.

This candidate also hardens existing viewer persistence without changing frozen PR5: transactional QueryFirst-style calls now receive exactly one scalar row for missing auth users (empty UUID sentinel) and duplicate viewer inserts (empty string sentinel). Source-only auth-lineage locks similarly return an empty scalar even with no auth row, and duplicate source inserts return an empty scalar. Existing rows are still locked by the scalar subqueries' `FOR UPDATE`. Empty insert results trigger disposal/rollback without updates or commit; conflicts can then be resolved through immutable service replay rather than an unexpected no-row exception.

Source and viewer provenance hashes require exactly 64 lowercase hexadecimal characters; trailing LF/CRLF is invalid SHA256 metadata. This format guard does not trim or normalize raw service-geography fields.

DB-free checks: `dotnet run --project tests/SourceAccountContractTest/SourceAccountContractTest.csproj` compiles actual source DTO/policy and exercises raw values, identity uniqueness/immutability, safe source shape, viewer compatibility and historical/hash guards. The existing `tests/ResourceSmokeTest` runner adds actual service/controller fixtures with fake stores, including simulated identity/pair/replay races (not a real PostgreSQL concurrency claim). Native API/fixture builds require the existing private packages. No external database, stack, model or server is started by these fixtures.
